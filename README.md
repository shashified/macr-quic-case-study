# QUIC vs TCP+TLS under Client Mobility, and Migration-Aware Careful Resume (MACR)

Case study for **BACSE203 Computer Networks (Fall 2026)**, School of Computer Science and Engineering, VIT Vellore.
Faculty: Dr. T. Thiruvenkadam. Team MACR: Shashank Tiwari, Tanmay Dawande, Riddhi Gupta, Kyra Panwar.

The final report is in [`report/`](report/) as an IEEE-format paper (PDF and Word). It contains:

- **Part A, review paper:** QUIC versus TCP+TLS across connection set-up, multiplexing, congestion control and mobility, drawn from 26 RFCs and papers.
- **Part B, case study:** a Wireshark comparison of the TCP+TLS 1.3 and QUIC handshakes, plus a packet-level model of MACR.
- **Part C, alignment and limitations note:** how the results compare with the literature and what the experiments could not capture.

## The idea in one paragraph

When a QUIC connection migrates to a new network path, RFC 9000 resets its congestion controller. RFC 9959 (Careful Resume) reuses saved congestion state, but only for a *later* connection. MACR closes that gap. It caches congestion state per path inside one connection. When the client returns to a path, MACR re-enters through Careful Resume's safety phases: reconnaissance, a paced jump, validation, and safe retreat.

## Key results (packet-level model, 20 seeds per scenario)

| Scenario (median per return migration) | RFC 9000 reset | MACR |
|---|---|---|
| Uncontended 50 Mb/s path: own losses | 340 | 0 |
| High-BDP 100 Mb/s, 100 ms: time to 90% throughput | 1.0 s | 0.6 s |
| High-BDP: data delivered in the first 2 s | 15.69 MB | 19.42 MB |
| High-BDP: peak queuing delay | 104.2 ms | 0.4 ms |
| Established loss-based competitor: data in 2 s | 4.62 MB | 2.39 MB (negative result) |

In the Wireshark capture, the first response arrived after 53.9 ms over TCP+TLS 1.3 and after about 32.9 ms over QUIC. TCP+TLS needed two round trips before it could send the request; QUIC needed one.

## Running the simulator

Requires Python 3 with numpy, scipy and matplotlib. The results are deterministic because the seeds are fixed.

```bash
cd simulator
python3 -m venv .venv && source .venv/bin/activate
pip install numpy scipy matplotlib

# either everything at once
./run_all.sh

# or one scenario at a time, with live progress
for s in S1_d2 S1_d5 S1_d10 S2_hbdp S3_cont S4_join S5_rate; do python3 run_chunk.py $s; done
python3 run_chunk.py merge
python3 sweep.py && python3 analyse.py && python3 summary_tables.py
```

| File | Purpose |
|---|---|
| `macrsim.py` | Discrete-event simulator: links with drop-tail queues, NewReno senders with pacing, and the Careful Resume phases |
| `experiments.py` | Scenarios S1–S5, policies (RESET, CARRY, RESTORE, MACR) and ablations |
| `run_chunk.py` | Runs one scenario with a progress display, and merges the parts |
| `sweep.py` | Buffer-size sweep (0.25, 0.5 and 2 BDP) |
| `analyse.py` | Bootstrap confidence intervals and figures |
| `summary_tables.py` | Result table and seed-level Wilcoxon tests |
